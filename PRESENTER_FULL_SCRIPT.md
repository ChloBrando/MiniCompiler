# Presenter Script — Mini Compiler (Strings)

This is a single, polished script you can read aloud while pointing at the code. It explains the feature at a high level, then goes deeper into the implementation and the end‑to‑end flow (AST → TAC → MIPS). Language is technically correct but conversational.

---

Intro (10s)
"Today I’ll show the string feature we added to the Mini language. You can declare strings, store string literals, print them, and concatenate them. I’ll run a short demo and then explain how it works under the hood."

Short demo (optional, 10–15s)
- Open `Mini/test.c` and point at:
  `string s; s = "Hello, Mini!"; print(s);`
- Say: "This program stores a literal in a string variable and prints it. I’ll run it later so you can see the generated MIPS and the output."

High-level overview — one sentence each (30s)
- Lexer (`Mini/scanner.l`): breaks input into tokens. The string rule matches quoted text and produces a temporary C string.
- Parser (`Mini/parser.y`): checks syntax and builds the AST (calls like `createStringLit`, `createAssign`).
- AST (`Mini/ast.h` / `Mini/ast.c`): a tree representation of the program (declarations, expressions, prints, arrays, strings).
- Semantic pass (`Mini/semantic.c`): walks the AST, registers declarations in the symbol table, and computes expression types (int vs string).
- Symbol table (`Mini/symtab.c`): maps names to metadata and stack offsets; a string variable reserves one 4‑byte slot (a pointer); arrays reserve N × 4 bytes.
- TAC (`Mini/tac.c`): a simple three‑address intermediate form. `generateTACExpr()` and `generateTAC()` emit TAC so optimizations and codegen have an easy view of the program.
- Codegen (`Mini/codegen.c`): collects string literals into `.data`, emits `.text` via `genExpr()`/`genStmt()`, and uses a small runtime helper for concatenation.

Deep dive — step by step (read while pointing at the files)

1) Lexer: where the literal starts (open `Mini/scanner.l`)
- Show: the quoted string rule and the code that strips quotes and calls `strdup`/`malloc`.
- Say: "The lexer copies characters between quotes into a temporary heap buffer and sets `yylval.str` to point at it. The lexer’s buffer is temporary — ownership is passed to the parser action that receives the token."

2) Parser & AST: make the tree (open `Mini/parser.y` and `Mini/ast.h`)
- Show: the `STRING_LITERAL` action in `parser.y` and AST constructors in `ast.h`.
- Say: "When the parser sees a string token it calls `createStringLit($1)` to produce a `NODE_STR` AST node. After that it calls `free($1)` to release the lexer’s temporary buffer. The AST node retains whatever it needs for downstream passes."

3) Semantic analysis: types and declarations (open `Mini/semantic.c`)
- Show: `exprType()` and the checks in `checkStmt()`.
- Say: "The semantic pass walks the AST and records declarations in the symbol table. `exprType()` returns TYPE_INT or TYPE_STRING. For the `+` operator we accept int+int → int or string+string → string; mixed types are rejected. Declarations call `addVar` / `addStringVar` / `addArrayVar` which assign stack offsets."

4) Symbol table: what we store (open `Mini/symtab.c`)
- Show: `addStringVar`, `addArrayVar`, and `getVarOffset()`.
- Say: "The symbol table maps identifiers to metadata and stack offsets. A string variable stores a pointer in one 4‑byte slot; an array reserves contiguous 4‑byte slots. Code generation uses these offsets to load and store variables."

5) TAC: a simple IR (open `Mini/tac.c`)
- Show: `generateTACExpr()` and `generateTAC()`.
- Say: "
The main reason TAC exists is that it makes optimization and code generation simpler — assembly can be generated by walking the TAC list line by line. "

6) Code generation and `.data` (open `Mini/codegen.c`)
- Show: `collectStringLiterals(root)`, `generateMIPS()`, `genExpr()`, `genStmt()`.
- Say: "Before emitting code we collect unique literals and write them into `.data` as `str_literal_0: .asciiz "..."`. In `.text`, `genExpr` emits `la` to load literal addresses, `lw`/`sw` to read/write variable pointers, and syscalls to print values. For string concatenation `genExpr` sets `$a0/$a1` and calls `concat`, then uses the returned pointer in `$v0`."

7) Runtime concat helper (inside `generateMIPS()` in `codegen.c`)
- Show: the `concat:` label that `generateMIPS()` prints into the generated `.s` when needed.
- Say: "`concat` computes each string length, uses syscall 9 (sbrk) to allocate a new buffer of len1+len2+1 bytes, copies both strings into the new buffer, writes the NUL, and returns the pointer in `$v0`. This keeps concatenation logic in one place and the compiler code simple."

Worked example (short)
- Source: `string s; s = "Hi"; print(s);`
- Explain: "Parser makes nodes for decl, assign, print. TAC would show `DECL s`, `t0 = "Hi"`, `s = t0`, `PRINT s`. Codegen writes `.data` with `str_literal_0: .asciiz "Hi"`, loads that label into a temp, stores the temp into `s`'s stack slot, then loads it into `$a0` and calls syscall 4 to print."

How to run (one line)
In the `Mini/` directory:

```sh
make test && spim test.s
```
